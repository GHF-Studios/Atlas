# Permissions and Authority

> **Status:** Draft — use Identity and server-owned policy as authority sources.

Explain who may access a Project, author content, publish, or administer a service, and which component decides each permission. Steam browser identity, Steamworks verification, linked GitHub identity, Vapor roles, and publishing authority are distinct.

No client-supplied manifest field or UI role can make itself authoritative. Link to the current Identity and Registry contracts for exact decisions.
