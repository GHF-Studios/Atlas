# Knowledge Lifecycle

Atlas knowledge may begin as an observation, question, conversation, plan, or source finding. If it has no clear home, a proposed [Inbox](../08-inbox/README.md) might hold it temporarily; no intake process or review cadence is active.

A useful path is: capture → find a home and source → draft → human review → maintain, replace, or retire. Treat this as a model, not a mandatory pipeline. Work may loop back for more evidence, and writing a page to Git does not validate its claims. The [Sources and Evidence](../03-sources-and-evidence/README.md) guide explains how to keep claims tied to what their sources actually show.

This lifecycle describes how understanding changes over time. A [document status](../04-document-statuses/README.md) describes a page at one point; a [contribution process](../07-contribution-process/README.md) describes how a proposed edit is discussed. Atlas has no adopted promotion or review workflow yet. When a page is replaced, link its successor and preserve earlier context where it still matters.
