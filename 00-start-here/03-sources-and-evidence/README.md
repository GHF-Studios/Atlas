# Sources and Evidence

Atlas should make its important claims traceable. Link the closest source you used, and include its revision or date when that can change the answer. A link shows where a claim came from; it does not establish that the claim is true.

Different sources support different kinds of statements. Code and configuration at a named revision show what is present there, not that it builds or runs. A dated test, runtime, or operations report records what happened under its stated conditions. A plan or specification records intended direction at that time. Recollection can preserve context that was never written down, but attribute it and keep its limits visible.

When sources disagree, or stop short of the claim being made, show the gap instead of smoothing it over. One successful run does not establish behavior on every platform; one source snapshot does not establish what is deployed now. The [Evidence Levels](../../08-reference/documentation/evidence-levels/README.md) page lists useful source categories, not a formal ranking. Atlas has no adopted evidence-ranking policy or required citation format.

Never put credentials or secrets in Atlas.
