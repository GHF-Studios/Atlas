# Loo-Cast / Vapor research — current snapshot first

This guide points into the current-state audit, whose local worktree census was refreshed on October 26, 2026, and its historical reconstruction. It is not an additional source of authority.

## Revised research objective — explain the latest state, then its ancestry

The primary deliverable is a **semantic account of the latest accessible Loo-Cast/Vapor state**, across all checked-out repositories and relevant non-code material. Explain what each substantial product area and shared boundary does now, which repository and process owns it, what data or authority crosses that boundary, what it enables, and where its observed behavior diverges from the product's own contracts. Give this snapshot the deepest treatment: it is the accumulated design that needs explaining, not merely the last point in a chronology.

For every material current capability, assumption or boundary, cross-check the relevant accessible history: code and commit diffs, docs, plans, owner clarifications and corrections, reported behavior, proposals, reversals and abandoned approaches—including ideas that predate Vapor's name. Reconstruct how current behavior came to be and whether each older formulation is implemented, refined, superseded, contradicted or still unresolved. The timeline is supporting evidence for this explanation, not a substitute for it. Earlier prototypes receive less detail unless they explain a surviving idea, a reset, a repeated failure or a present ownership seam.

The working target is to inspect and triage **every current file** in the observed repository inventory, then deepen semantic review around central and high-risk paths; file-level exact-path coverage is a completion target; citations show that each source file was reached, while a separate semantic disposition records whether its behavior and relevant intent were reconciled. Connect the historical record by decision and design lineage rather than narrating every commit at equal depth. Clearly distinguish source-confirmed implementation, documentation, owner intent, reported behavior, interpretation and runtime verification. Never present inaccessible history or unchecked source as reconciled. “Everything” is the scope target, not a claim that unavailable records can be recovered: the app exposes bounded conversation history, the project mirror's `sources/` directory is empty, and no pre-Git 2021 archive has been found.

“October 26 source refresh” is the observation date, not a single commit date: the inspected roots have staggered heads (Loo-Cast October 22; most Vapor-Client children October 21–23; Platform Server October 22), plus the dirty and untracked project/source artifacts listed in the atlas. The October 26 check found no newer default-branch heads and preserved local dirty state. Claims must stay pinned to the relevant repository and local state.

The target is a systematic latest-snapshot audit across current files in every checked-out repository, cross-referenced against the accessible record of what was ever intended: owner decisions and corrections, reported behavior, code, docs, plans, product claims, commit diffs, reversals, and the older conversation/design corpus. For each current boundary, ask what it does now, what its ownership actually is, what was promised or assumed about it, how it changed, and whether earlier proposals were implemented, superseded, contradicted, or simply left dangling. This is broader than a chronology and broader than a code review: a current behavior must be compared with every relevant prior formulation, and every surviving or explicitly abandoned idea must be located against current implementation or marked unresolved. The latest snapshot should be explained more deeply than earlier prototypes because it carries the accumulated architecture and its most consequential seams. Early Unity/prototype files do not get equal detail unless they explain a surviving idea, a reset, a repeated failure, or an ownership seam. Maintain explicit coverage and exclusion notes; repository counts or a commit register never stand in for semantic review. Claims keep evidence class visible: implemented, documented, owner-directed, proposed, reported, interpreted, or runtime-verified. The latest pass now enumerates 1,540 non-ignored files across all 15 checked-out Git roots, not just code, while retaining the narrower 913-file executable-source register; the full inventory is a triage ledger, not proof of line-by-line review. “Everything” is the research target, not a promise that inaccessible or unreviewed material has been covered: the audit is substantial but does **not** yet certify that every current source file or every relevant past intention has been reconciled. The October 26 Platform Server recheck corrected a stale local-health-check finding: Registry is now probed locally, while state export/restore still omit it from their service-quiescing lists. The current-state cross-reference distinguishes this verified source state from live VPS state; no remote server was queried in that check.
